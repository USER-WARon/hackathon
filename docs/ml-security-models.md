# ShadowGuard ML Security Signals

## Runtime behavior

The backend loads the saved model bundle once during FastAPI startup. The bundle
contains a `RandomForestClassifier` trust model and a TF-IDF plus Logistic
Regression intent model. It is generated by running this command from
`backend`:

```powershell
python scripts\train_ml_models.py
```

If the artifact cannot be loaded or inference fails, the trust evaluator returns
no ML or combined score and classifies the source as `LOW_TRUST`. The intent
evaluator returns `UNCERTAIN`. It does not generate substitute scores.

Trust fusion defaults to:

```text
combined_trust_score = 0.70 * weighted_trust_score + 0.30 * ml_trust_score
threshold = 70
```

These settings can be changed on the backend with
`SHADOWGUARD_TRUST_WEIGHTED_WEIGHT`, `SHADOWGUARD_TRUST_ML_WEIGHT`, and
`SHADOWGUARD_TRUST_THRESHOLD`. The weights must be finite, between 0 and 1, and
sum to 1; an invalid configuration fails closed. Trust classifications are
limited to `HIGH_TRUST` and `LOW_TRUST`. Identity, authentication, permission,
behavior, and applicable policy checks can force `LOW_TRUST` regardless of the
combined score. The model never grants authorization.

The intent model returns `INTENDED`, `POTENTIALLY_UNINTENDED`, or `UNCERTAIN`.
Deterministic capability checks remain authoritative. A
`POTENTIALLY_UNINTENDED` result adds a block and an audit reason code;
`UNCERTAIN` is recorded as a signal and does not grant or expand permissions.

## Security boundaries and limitations

The current registry is per tool and has no separate MCP-server entity. The
trust model therefore evaluates registered tool records with the identity,
authentication, permissions, behavior, sensitivity, and relationship fields
already present. Optional `transport_secure`,
`tool_definition_integrity_valid`, `output_provenance_valid`, and
`policy_compliant` values are consumed when supplied. Explicit failed transport,
definition-integrity, or policy-compliance evidence prevents `HIGH_TRUST`.
Missing optional metadata is represented as missing model input, not asserted
to be secure.

Returned-data trust remains separate: `ResponseGuard`, taint state, and
provenance events continue to assess tool output. The optional
`output_provenance_valid` metadata feature does not mark a specific response as
trusted. A `HIGH_TRUST` source still does not authorize destructive work or
actions outside the request's deterministic authorized scope.

No suitable labeled operational dataset exists in the repository. The trainer
uses a documented synthetic demonstration dataset generated from explicit
security and intent-mismatch scenarios. Its held-out metrics are useful for
reproducibility and wiring checks only; they are not evidence of real-world
security performance. Collect and review representative labeled data before
using these models as production-quality classifiers.

## Synthetic evaluation

The trainer uses a fixed random seed and stratified 75/25 train/test splits.
Confusion matrices use the class orders shown below; rows are actual labels and
columns are predicted labels.

### Trust Random Forest

Class distribution: `HIGH_TRUST` 180 and `LOW_TRUST` 180; train 135/135, test
45/45.

| Class | Precision | Recall | F1 |
| --- | ---: | ---: | ---: |
| HIGH_TRUST | 1.000 | 1.000 | 1.000 |
| LOW_TRUST | 1.000 | 1.000 | 1.000 |
| Macro average | 1.000 | 1.000 | 1.000 |

Confusion matrix, order `HIGH_TRUST`, `LOW_TRUST`:

```text
[[45, 0],
 [ 0, 45]]
```
